# Задача для агента: Moo v2 — кабинеты фермера и ветеринара

Ты дорабатываешь PWA «Moo» (Нижний-Чуй, Кыргызстан). Прочитай ПО ПОРЯДКУ:
1. `architecture.md` — что строим и зачем (главная цепочка: срок → напоминание → запись → приём → подтверждение вета → кубок).
2. `reference-prototype.html` — ЭТАЛОН внешнего вида и поведения. Открой в браузере, пройди сценарий: фермер «Записаться» → переключи роль (кнопка вверху) на ветеринара → «Привит» → вернись в фермера (салют, кубок, +очки). Копируй структуру разметки и CSS оттуда, логику — адаптируй под наш код.
3. Текущие `index.html`, `styles.css`, `app.js`, `store.js`, `schema.sql`, `i18n.js`.

## Почему раньше вышло криво
Новый стиль накладывали ПОВЕРХ старого `styles.css`, и правила спорили (белые инпуты, transform у нижней навигации, липкий чат, перекрытия, смесь языков). **Не накладывай. Замени `styles.css` целиком** на один стиль из `reference-prototype.html` (блок `<style>`): токены `:root`, `.glass`, `.btn`, `.nav`, `.card`, `.row`, `.chip`, `.bar`, `.sheet`, переключатель `.tgl`, фоны `.bgl` на каждую вкладку (картинки в `img/`). Старые правила удали. Проверь на ширине 360–440px, светлая и тёмная тема.

## Что сделать (в этом порядке, после каждого шага — проверка в браузере)
1. **Дизайн.** Замена `styles.css`, шапка (лого, кнопка роли, переключатель день/ночь), нижняя навигация на 5 вкладок, фон меняется по вкладкам. Весь текст через `i18n.js` (ru/ky/en), никаких захардкоженных английских строк и смеси языков в моках.
2. **Роль.** Читать `profiles.role` (`farmer`/`vet`). Для демо оставить кнопку переключения роли за флагом `DEMO_ROLE_SWITCH = true`. Код `VET-2026` из браузера УДАЛИТЬ.
3. **Срок прививки у животного.** Вычислять статус `ok/soon/urgent/overdue/never` из последней подтверждённой прививки (`valid_until = done_at + 365`). На «Главной» у каждого животного: полоса срока, «Привита … · до …», метки 30/7/1. Напоминания на 30/7/1 день и при просрочке (тосты при входе; позже Web Push через `sw.js`). Просрочка → кубок серый «потерян».
4. **Запись.** Слоты вета (`slots`) показываются в ленте карточкой «Занято X из Y», кнопка «Записаться» → лист выбора животных → номер в очереди и время. Запись вызывает SQL-функцию `book_slot` (атомарно). «Моя запись» на «Главной» и закреплённой карточкой в чате с ветом. Отмена записи.
5. **Кабинет ветеринара** (5 вкладок): Сегодня (слоты, очередь, «Привит»/«Не пришёл», «Открыть приём» + публикация в ленту), Карта (дома по статусам, фильтры, очаги, карточка дома с «Написать»/«На приём»), Рассылки (сегмент → текст → отправка + в ленту), Чаты (входящие по фермерам), Статистика (% привитости, по видам, 7 дней, кому написать).
6. **Награды только за подтверждённое.** Кубок и очки — когда вет нажал «Привит» (`vaccinations.status='verified'`). Самоотметка фермера кубок не даёт (убрать кнопку «Отметить прививку»). Очки считать на сервере (функция/триггер), не в браузере.
7. **Чат с ветом:** `messages.thread` = id фермера; RLS: фермер видит только свой тред, вет — все личные.

## База данных
Черновик SQL — в конце `architecture.md` (раздел 14). **Не применяй SQL к боевой базе без моего подтверждения.** Сначала покажи миграцию отдельным файлом `schema-v2.sql`, обнови `store.js` так, чтобы без Supabase всё работало на localStorage (как сейчас), а схему при отсутствии новых таблиц использовал fallback (`isSchemaError`).
