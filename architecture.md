# Moo — архитектура продукта (v2)

> Одна идея: **«Moo не даёт забыть про прививку — и награждает за неё»**.
> Всё остальное (морда, карта, чат, рейтинг) — инструменты вокруг этой цепочки.

## 1. Главная цепочка (ядро продукта)

```
Срок прививки ─► Напоминание ─► Запись к вету ─► Приём ─► Подтверждение ─► Награда
 (у животного)   (30/7/1 дн.)    (слот в ленте)   (очередь)  (вет в приложении)  (кубок + очки)
        ▲                                                                           │
        └───────────────── новый срок = дата прививки + 365 дн. ◄──────────────────┘
```

Каждая фича приложения обязана быть звеном этой цепочки. Если не является — откладываем.

**Ключевое правило честности:** кубок и очки даёт только прививка, **подтверждённая ветеринаром**.
Самоотметка фермера = «заявлено» (жёлтый статус), без наград. Это защищает рейтинг от накрутки.

## 2. Роли

| Роль | Кто | Как определяется |
|---|---|---|
| `farmer` | житель села | по умолчанию |
| `vet` | ветеринар | `profiles.role = 'vet'`, назначает администратор (не код в браузере) |

Один аккаунт — одна роль. После входа приложение показывает **кабинет по роли**.

## 3. Сущности (данные)

| Сущность | Поля (главное) | Зачем |
|---|---|---|
| `profiles` | id, name, phone, role, house_id | пользователь |
| `animals` | id, owner_id, species, name, muzzle_embedding | животное (как сейчас) |
| `vaccinations` | id, animal_id, disease, done_at, valid_until, status (`claimed`/`verified`), verified_by, booking_id | история прививок; **valid_until = done_at + 365** |
| `slots` | id, vet_id, date, time_from, time_to, capacity (голов), booked (голов), place, disease | приём на день, публикуется в ленте |
| `bookings` | id, slot_id, farmer_id, animal_ids[], heads, queue_no, status (`booked`/`came`/`done`/`no_show`/`cancelled`) | запись и очередь |
| `threads` / `messages` | thread (= farmer_id для чата с ветом, `village` для общего), sender_id, text, booking_id? | чаты |
| `broadcasts` | id, vet_id, segment, text, post_to_feed, created_at | рассылки по сегментам |
| `posts` | id, author_id, kind (`slot`/`alert`/`user`), text, slot_id? | лента |
| `rewards_state` | user_id, trophies, points, streak | кубки и очки (потом `activity_log`) |
| `activity_log` | user_id, kind, points, at | будущие ежедневные задания (кормёжка, уборка…) |

### Статус животного (вычисляется, не хранится)
Считается из последней **verified** прививки:

| Статус | Условие | Цвет |
|---|---|---|
| `ok` | осталось > 30 дн. | зелёный |
| `soon` | 8–30 дн. | жёлтый |
| `urgent` | 1–7 дн. | оранжевый |
| `overdue` | срок прошёл | красный |
| `never` | прививок нет | серый/красный |
| `claimed` | отметил сам, вет не подтвердил | пунктир |

## 4. Напоминания (трекинг срока)

- Точки напоминаний: **за 30, 7 и 1 день** до `valid_until`, плюс при просрочке.
- Показываются: (а) плашка на «Главной» по каждому животному («Бурёнка: 12 дней до прививки»), (б) всплывающее уведомление при входе, (в) позже — push (Web Push через `sw.js`).
- Показанные напоминания помнятся (`rewards_state`), чтобы не повторяться.
- Просрочка → кубок за это животное **сгорает** → в «Кубках» он серый с подписью «потерян».

## 5. Запись и очередь (связь фермер ↔ вет)

1. **Вет** публикует слот: «Вторник, 9:00–13:00, площадь у школы, ящур, принимаю 30 голов».
2. Слот **автоматически появляется в ленте** карточкой с полосой «Занято 12/30» и кнопкой «Записаться».
3. **Фермер** жмёт «Записаться», выбирает животных (кол-во голов ≤ осталось) → получает **номер в очереди** («Вы № 7, ориентировочно 10:20»).
4. Записи фермера видны в «Главной» блоком «Моя запись».
5. Вет в кабинете видит **очередь** (список по номерам), отмечает «пришёл» → «привит» (по каждому животному).
6. «Привит» создаёт `vaccinations(status=verified)` → фермеру приходит уведомление + кубок + очки + новый срок.
7. Не пришёл → `no_show` (место освобождается; позже: штраф баллов).
8. У каждой записи есть кнопка **«Написать вету»** → открывает личный чат с привязкой к записи.

Защита от перебора: `heads ≤ capacity − booked` проверяется на сервере (в SQL-функции `book_slot`), а не в браузере.

## 6. Чаты

- **Общий чат села** — как сейчас (`thread = 'village'`).
- **Чат с ветом** — личный: `thread = farmer_id`. Фермер видит только свой, вет видит **входящие** (список фермеров, непрочитанные сверху).
- RLS: фермер читает/пишет только в `thread = auth.uid()`; вет — во все личные.

## 7. Рассылки и публикации (инструменты вета)

Сегменты (по статусу животных):
- `overdue` — просрочили;
- `urgent` — осталось ≤ 7 дн.;
- `soon` — осталось ≤ 30 дн.;
- `never` — ни разу не привиты;
- `all` — все.

Действия:
- **Отправить личные сообщения** сегменту (в чаты с ветом, шаблон с подстановкой имени и животного);
- **Опубликовать в ленту** (`post kind=alert`) — одной кнопкой вместе с рассылкой;
- Авто-шаблоны: «Приём во вторник, записывайтесь», «Срок прививки истекает на этой неделе».

## 8. Карта

- **Фермер:** видит дома соседей, свой дом; **красных меток нет**.
- **Вет:** дома окрашены по худшему статусу животных: 🟢 ок / 🟡 скоро / 🟠 срочно / 🔴 просрочено / ⚪ не привиты; фильтр «за последние N дней»; очаги болезней (красные круги) поверх. Тап по дому → хозяин, животные, кнопка «Написать» и «Пригласить на приём».

## 9. Статистика села

- Ядро: **% привитых** (животных с `ok/soon/urgent` из всех), по видам скота, по секторам.
- Фермеру показывается **агрегат** («Нижний-Чуй привит на 64%») — мотивация, без имён.
- Вету — агрегат + списки и динамика за 7/30 дней, «охват приёма» (записано/принято).

## 10. Приватность

| Что | Фермер | Вет |
|---|---|---|
| Свои животные и прививки | ✅ | — |
| Чужие животные | ❌ только имя в рейтинге | ✅ статус и хозяин |
| Красные метки/очаги | ❌ | ✅ |
| Статистика села | ✅ агрегат | ✅ полная |
| Личный чат | свой | все личные |

## 11. Кабинеты — карта экранов

### Кабинет фермера (5 вкладок)
| Вкладка | Что внутри |
|---|---|
| 🏠 Главная | «Пора привить: N», карточка **«Моя запись» (№ в очереди)**, «Найти животное» (камера), **по каждому животному: полоса срока, дата прививки, метки 30/7/1, кнопка «Записаться»**, привитость села в % |
| 📰 Лента | карточки приёма (занято X/Y, «Записаться»), объявления вета, посты села |
| 💬 Чат | «Село» / «Ветеринар» (закреплена моя запись) |
| 🗺 Карта | дома без статусов и без красных меток |
| 🏆 Рейтинг | переключатель «Рейтинг / Мои кубки», топ недели/всего |

Профиль открывается кнопкой справа вверху на «Главной».

| Вкладка | Что внутри |

| 🗺 Карта | дома по статусам, очаги, фильтр по давности |

| 📊 Статистика | % привитости села, по видам, динамика, список «должники» |

## 12. Демо-сценарий для жюри (90 секунд)

1. Вет создаёт слот «Завтра, 30 голов» → он сразу в ленте.
2. Фермер видит напоминание «Бурёнка: 6 дней до прививки» → жмёт «Записаться» → «Вы № 3».
3. Вет в очереди жмёт «Привит» → у фермера **салют, кубок, +100 очков**, рейтинг пересчитался.
4. Вет открывает карту: дом стал зелёным; запускает рассылку «просрочившим» одним касанием.
5. Статистика села: 64% → 66%.

## 14. Что поменять в БД (черновик SQL, не применять без подтверждения)

```sql
alter table profiles add column if not exists role text not null default 'farmer';

create table slots (
  id uuid primary key default gen_random_uuid(),
  vet_id uuid references profiles(id),
  day date not null, time_from time not null, time_to time not null,
  place text, disease text, capacity int not null check (capacity > 0),
  booked int not null default 0,
  created_at timestamptz default now()
);

create table bookings (
  id uuid primary key default gen_random_uuid(),
  slot_id uuid references slots(id) on delete cascade,
  farmer_id uuid references profiles(id),
  animal_ids uuid[] not null, heads int not null check (heads > 0),
  queue_no int not null,
  status text not null default 'booked',
  created_at timestamptz default now()
);

create table vaccinations (
  id uuid primary key default gen_random_uuid(),
  animal_id uuid references animals(id) on delete cascade,
  disease text not null, done_at date not null, valid_until date not null,
  status text not null default 'claimed',      -- claimed | verified
  verified_by uuid references profiles(id),
  booking_id uuid references bookings(id)
);

create table broadcasts (
  id uuid primary key default gen_random_uuid(),
  vet_id uuid references profiles(id),
  segment text not null, text text not null, post_to_feed boolean default false,
  created_at timestamptz default now()
);

alter table messages add column if not exists thread text not null default 'village';
alter table messages add column if not exists booking_id uuid;
```

Функция записи (атомарно, чтобы не перебрали места):
```sql
create function book_slot(p_slot uuid, p_animals uuid[]) returns bookings
language plpgsql security definer as $$
declare s slots; b bookings; n int := array_length(p_animals,1);
begin
  select * into s from slots where id = p_slot for update;
  if s.booked + n > s.capacity then raise exception 'no_capacity'; end if;
  update slots set booked = booked + n where id = p_slot;
  insert into bookings(slot_id, farmer_id, animal_ids, heads, queue_no)
  values (p_slot, auth.uid(), p_animals, n, s.booked + 1) returning * into b;
  return b;
end $$;
```

RLS: `bookings` — фермер видит свои, вет — все свои слоты; `vaccinations.status='verified'` пишет только `role='vet'`.
